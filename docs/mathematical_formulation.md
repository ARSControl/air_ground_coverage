## Implemented decentralized aerial HEDAC core

The opt-in decentralized aerial controller follows the local coverage and heat
construction of equations (14)--(19) in
`docs/biblio/Distributed_Multi-Robot_Ergodic_Coverage_Control_for_Estimating_Time-Varying_Spatial_Processes.pdf`.
It does **not** create a GP per robot: all aerial robots consume the same latest
target density supplied by the simulation-owned central multi-fidelity
estimator. Only coverage memory and the heat controller are decentralized.

For outer control step $k\geq 1$, aerial robot $i$ rasterizes its instantaneous
Gaussian footprint $p_i^k(q)$ using the existing HEDAC coverage block and keeps
the exact discrete running mean

$$
c_i^k(q)=\frac{(k-1)c_i^{k-1}(q)+p_i^k(q)}{k}.
$$

All positions are snapshotted before any robot moves. With configured range
$r>0$, the current undirected neighbor set is

$$
\mathcal N_i^k=\{j\neq i:\lVert z_j^k-z_i^k\rVert_2\leq r\}.
$$

The implemented first version uses the paper's hard spatial support

$$
w_r(q,z_i^k)=\mathbf 1[\lVert q-z_i^k\rVert_2\leq r]
$$

and constructs the local aggregate from immutable same-step coverage snapshots,

$$
\widetilde c_i^k(q)
=c_i^k(q)+\sum_{j\in\mathcal N_i^k}w_r(q,z_i^k)c_j^k(q).
$$

Let $g_H^k$ be the normalized aerial target derived from the latest central
HIGH-field posterior, or the static initial target before the first posterior.
Each robot independently computes the implemented raster source

$$
s_i^k(q)=
\operatorname{normalize}_{\Omega_f}
\left(\max\left[g_H^k(q)
-\operatorname{normalize}_{\Omega_f}(\widetilde c_i^k)(q),0\right]^2\right)
|\Omega_f|,
$$

then advances its own explicit finite-difference heat field with the same CFL
limiting, diffusion, source, and domain-decay coefficients as centralized
HEDAC. All gradients and commands are computed before any dynamics update, so
the result does not depend on robot iteration order. The returned scalar
ergodic metric remains a read-only team diagnostic computed from
$\sum_i c_i^k$ and the static truth target; it never feeds back into control.

Implementations: `src/core/decentralized_hedac.py` and the reusable numerical
operations in `src/core/hedac.py`. The deterministic real-output visualization
is generated by `examples/plot_decentralized_hedac_core_milestone.py`.

artifact. The PDF is generated from source and is intentionally not committed to

## Implemented circular ground obstacles

The coupled builder maintains two occupancy rasters. $M^A_{yx}$ is the loaded
aerial/HEDAC map. Generated circles are added only to the ground map $M^G$;
aerial robots can overfly them. Robot motion and controller grids use raster
index coordinates, so the production obstacle rasterizer uses cell centre
$\mathbf q_{yx}=(x,y)^\top$ even when the HEDAC heat discretization has another
physical cell-size parameter. With obstacle count $K_o$ and common radius
$R_o$, the obstacle RNG uses the episode-derived seed
$s_o=s+30000$. Candidate centres are sampled uniformly inside the inset map
boundary and accepted sequentially only when

$$
\|\mathbf c_k-\mathbf c_l\|_2>2R_o
\qquad \text{for every previously accepted }l.
$$

The exact rasterization and ground-map union are

$$
O_{yx}
=
\mathbf 1\!\left[
\min_{k=1,\ldots,K_o}\|\mathbf q_{yx}-\mathbf c_k\|_2\le R_o
\right],
\qquad
M^G_{yx}=\max(M^A_{yx},O_{yx}).
$$

Zero obstacles produce an all-free generated raster. An infeasible radius or
an obstacle set that cannot be placed without overlap is rejected rather than
silently reducing the requested count. By default, robot initial positions
retain the historical uniform-free-cell sampling. The composition experiment
instead uses a common lower-left corner deployment. For robot class
$r\in\{A,G\}$, map width $W$, height $H$, and $\gamma=0.2$, its candidate set
is

$$
\mathcal C^r
=
\{(x,y):M^r_{yx}=0,\ 0\le x<\gamma W,\ 0\le y<\gamma H\}.
$$

The aerial and ground candidate permutations use episode-derived seeds
$s_A=s+40000$ and $s_G=s+50000$, respectively. The first $N_r$ permuted cells
are assigned to class $r$ without replacement; headings are subsequent draws
from $\mathcal U[0,2\pi)$. Thus a class's first initial states are nested
across compositions for the same episode. An undersized candidate set is
rejected rather than expanded silently.

The hidden HIGH field is zeroed on $M^G=1$;
nearest-cell samples of $M^G$ form the estimator and evaluation free-query
mask. Hence the published ground density and every reconstruction metric omit
obstacle queries. Aerial HEDAC motion still uses $M^A$.

For the Lloyd controller, let $\mathcal O_i$ be occupied cell centres within
the influence distance $R_I=\max(2,2.5R_o)$ of ground robot $i$. For
$d_{il}=\|\mathbf p_i-\mathbf o_l\|_2$, the implementation computes

$$
\mathbf r_i=
\operatorname{clip}_{\|\cdot\|\le1}
\left[
\sum_{l\in\mathcal O_i}
\frac{R_I-d_{il}}{R_I}
\frac{\mathbf p_i-\mathbf o_l}{d_{il}}
\right]
$$

and replaces the centroid displacement by

$$
\widetilde{\mathbf e}_i
=
\mathbf c_i-\mathbf p_i
+w_o\max(\|\mathbf c_i-\mathbf p_i\|_2,1)\mathbf r_i,
$$

where $w_o$ is `ground.agents.wall_avoidance_weight`. The ordinary Lloyd
heading and speed law uses $\widetilde{\mathbf e}_i$. A final discrete safety
guard predicts the heading-first unicycle segment and samples it at spacing no
greater than $0.25$ map units. Translation is set to zero if any sample is
outside the raster or occupied; the clipped angular command is still applied
so the robot can turn away. The same guard is applied to the legacy MPC path
when that path uses a unicycle agent. The guard is bypassed exactly when the
map contains no obstacles, preserving prior obstacle-free motion.

Implementations: `src/core/obstacles.py`, `src/coupled_simulation.py`, and the
ground-map and initialization-policy recording in
`evaluation/run_multifidelity_composition.py`.

## Implemented obstacle-aware sensor visibility

Both central multi-fidelity sensors use the shared ground occupancy raster
$M^G$ when accepting a continuous candidate observation. For robot position
$\mathbf p$, candidate position $\mathbf q$, configured range $R$, and angular
field of view $\operatorname{FOV}(\mathbf p)$, the exact implemented admission
condition is

$$
a(\mathbf p,\mathbf q)
=
\mathbf 1[\|\mathbf q-\mathbf p\|_2\le R]
\mathbf 1[\mathbf q\in\operatorname{FOV}(\mathbf p)]
\mathbf 1[\operatorname{LOS}_{M^G}(\mathbf p,\mathbf q)].
$$

The range and angular conditions are enforced by the existing area-uniform
sector proposal. For line of sight, occupied raster cell $(y,x)$ represents
the closed unit square centred at $(x,y)$. The predicate
$\operatorname{LOS}_{M^G}=1$ exactly when the closed segment
$[\mathbf p,\mathbf q]$ intersects none of those occupied squares. Boundary or
tangent contact is therefore conservatively occluded, and a candidate whose
nearest raster cell is occupied is rejected. Both endpoints must lie in the
map's centre-coordinate bounds.

Each requested observation is rejection-sampled up to the configured attempt
limit. Out-of-bounds and occluded candidates are discarded before measurement
noise is drawn. If no admissible candidate is found, that observation
opportunity produces no sample; consequently a collection event may return
fewer than the configured per-robot count, including an empty batch. Empty
batches leave estimator scheduling and the latest valid posterior unchanged.
On an obstacle-free raster the LOS predicate is identically true, so the
accepted-position law remains the original area-uniform sector law.

This 2-D implementation applies the same occupancy raster to LOW aerial and
HIGH ground sampling even though aerial motion may overfly ground obstacles.
It therefore models obstacles as vertically occluding the sensed field; no
obstacle-height or altitude model is currently implemented.

Implementations: `src/core/obstacles.py` for the conservative segment/raster
test, `src/models/sensors.py` for rejection sampling, and `src/simulation.py`
for wiring the common obstacle raster into both sensors.

## Implemented zero-mass posterior-density fallback

Let $M_j$ be the free-query mask, $w_j$ the integration weights,
$\mu^+_{H,j}=\max(\mu_{H,j},0)$, and
$Z=\sum_jM_j\mu^+_{H,j}w_j$. The controller-density input is

$$
v_j=
\begin{cases}
\mu^+_{H,j}, & Z>0,\\
1, & Z=0,
\end{cases}
\qquad
\phi_j=\frac{M_jv_j}{\sum_kM_kv_kw_k}.
$$

Thus a completely nonpositive first posterior publishes a uniform free-space
density instead of failing normalization. The raw posterior mean and variance
are unchanged, so reconstruction metrics still evaluate the actual GP output.
Other update failures continue to preserve the latest valid snapshot.

Implementation: `src/core/multifidelity_estimator.py`.

## Implemented team-composition reconstruction evaluation

The closed-loop composition sweep fixes the total team size $N=N_a+N_g$ and
changes only the number of aerial and ground robots. The publication protocol
uses $N=10$ and aerial counts $N_a\in\{10,2,0\}$. Every condition runs the
same coupled simulation and autoregressive MFGP; no endpoint substitutes a
different estimator. Two named scenarios supply declared mission and ground
geometry parameters:

$$
(K_s,T_s,n_{o,s},r_{o,s})
=
\begin{cases}
(200,20,5,1), & s=\texttt{easy\_long},\\
(100,10,15,2), & s=\texttt{hard\_short},
\end{cases}
$$

where $K_s$ is the number of integration steps, $T_s=K_s\Delta t$ seconds,
$n_{o,s}$ is the number of ground obstacles, $r_{o,s}$ is their radius, and
$\Delta t=0.1$ s. Both geometry and duration change between scenarios, so the
implemented comparison evaluates bundled operating regimes and does not
identify either factor independently.

For composition $c$, episode $e$, and posterior publication $r$, let
$\mathcal J_{c,e}$ be the free query cells. Define the nonnegative evaluated
reconstruction $\mu^+_{H,c,e,r,j}=\max(\mu_{H,c,e,r,j},0)$. The implemented
field error is

$$
\operatorname{NRMSE}_{c,e,r}
=
\frac{
\sqrt{\frac{1}{|\mathcal J_{c,e}|}
\sum_{j\in\mathcal J_{c,e}}
(\mu^+_{H,c,e,r,j}-f_{H,c,e,j})^2}
}{
\max_{j\in\mathcal J_{c,e}}f_{H,c,e,j}
-\min_{j\in\mathcal J_{c,e}}f_{H,c,e,j}
}.
$$

Let $w_j$ be the integration weight and $\phi_{c,e,j}$ the normalized hidden
truth density. The posterior density is clipped to a positive numerical floor,
renormalized with the same weights, and evaluated using

$$
D_{\mathrm{KL},c,e,r}
=
\sum_{j:\phi_{c,e,j}>0}
w_j\phi_{c,e,j}
\log\!\left(\frac{\phi_{c,e,j}}{\widehat\phi_{c,e,r,j}}\right).
$$

For the probabilistic field score, define
$\widetilde\sigma^2_{H,c,e,r,j}=\max(\sigma^2_{H,c,e,r,j},10^{-12})$.
The implemented integration-weighted marginal Gaussian negative log predictive
density is

$$
\operatorname{NLPD}_{c,e,r}
=
\frac{1}{\sum_{j\in\mathcal J_{c,e}}w_j}
\sum_{j\in\mathcal J_{c,e}}w_j
\left[
\frac{1}{2}\log(2\pi\widetilde\sigma^2_{H,c,e,r,j})
+
\frac{(f_{H,c,e,j}-\mu_{H,c,e,r,j})^2}
{2\widetilde\sigma^2_{H,c,e,r,j}}
\right].
$$

NLPD uses the raw latent HIGH posterior mean and variance: it applies neither
nonnegative clipping nor density normalization and does not add sensor noise.
It evaluates independent marginal predictive densities at the query cells, not
their joint cross-query covariance. Lower is better, and well-calibrated narrow
continuous densities can yield negative values.

The nonnegative clipping is applied before NRMSE only; no density normalization
is applied to either field score. The secondary calibration diagnostic
intentionally remains centred on the raw GP mean because it evaluates the
Gaussian posterior:

$$
C_{95,c,e,r}
=
\frac{1}{|\mathcal J_{c,e}|}
\sum_{j\in\mathcal J_{c,e}}
\mathbf 1\!\left[
|f_{H,c,e,j}-\mu_{H,c,e,r,j}|
\le 1.96\sqrt{\sigma^2_{H,c,e,r,j}}
\right].
$$

For any posterior metric $m_r$ published at times
$t_0<\cdots<t_R\le T_s$, the offline evaluator holds the latest value to the
selected scenario horizon $T_s$ and computes the exact implemented trapezoidal
average

$$
\overline m
=
\frac{1}{T_s-t_0}
\left[
\sum_{r=0}^{R-1}
\frac{m_r+m_{r+1}}{2}(t_{r+1}-t_r)
+m_R(T_s-t_R)
\right].
$$

To prevent mixed teams from receiving a larger GP training set merely because
the estimator has two fidelity buffers, one active retention budget $B$ is
split in proportion to composition. For $N_a,N_g>0$, the implemented caps are

$$
B_L=\left\lfloor B\frac{N_a}{N}\right\rfloor,
\qquad
B_H=B-B_L.
$$

At a homogeneous endpoint, the active fidelity receives $B$ and the inactive
buffer receives an unused placeholder cap of one because the retention class
requires a positive capacity. LOW and HIGH sensing use the same event period
and the same samples per robot per event, so the total observation opportunity
per sensing event is constant at $sN$. Submitted LOW/HIGH counts and retained
counts are saved and never feed back into evaluation.

The composition experiment uses online empirical-Bayes kernel fitting. Every
composition and episode starts from the same configured parameter vector
$\boldsymbol\theta_0=(\ell_L,\sigma_L^2,\ell_\delta,\sigma_\delta^2)$ and uses
the same bounds, sample threshold $M_{\min}$, fit interval $K_{\mathrm{fit}}$,
restart count, and iteration limit. For the candidate that would publish
posterior version $r\ge1$, the implemented schedule is

$$
\boldsymbol\theta_{c,e,r}
=
\begin{cases}
\displaystyle\arg\min_{\boldsymbol\theta\in\mathcal B}
\mathcal L_{c,e,r}(\boldsymbol\theta),
& n_{L,c,e,r}+n_{H,c,e,r}\ge M_{\min}
\ \text{and}\ (r-1)\bmod K_{\mathrm{fit}}=0,\\
\boldsymbol\theta_{c,e,r-1}, & \text{otherwise}.
\end{cases}
$$

Thus the optimization policy is controlled across conditions, but the fitted
kernel values are data-dependent and are not constrained to match between
compositions or scenarios. At A10/G0 the discrepancy-kernel parameters are not
identified by LOW data; at A0/G10 the LOW and discrepancy covariance components
are not separately identified from HIGH data alone. These endpoint values are
therefore diagnostics of the bounded optimizer, not independent physical
estimates. Every posterior record saves the fit flag, optimization duration,
and all four realized kernel parameters.

For the ten-robot publication protocol, $B=400$ and the ordered
$(B_L,B_H)$ caps are $(400,1)$, $(80,320)$, and $(1,400)$ for A10/G0, A2/G8,
and A0/G10; the `1` values are inactive placeholders. With $s=10$ samples per
active robot and a shared sensing period of $0.5$ s, every composition submits
100 observations at each sensing event. The sole publication scenario,
`easy_long`, lasts 30 s, contains 60 events, and submits 6000 observations per
episode. The total opportunity is independent of composition and is split
between fidelities in proportion to team makeup.

Implementations: `evaluation/run_multifidelity_composition.py`,
`evaluation/evaluate_multifidelity_composition.py`,
`evaluation/plot_multifidelity_composition.py`, and
`evaluation/plot_multifidelity_scenario_comparison.py`,
`evaluation/plot_multifidelity_composition_trajectories.py`,
`evaluation/run_multifidelity_scenario_pipeline.py`, and
`evaluation/multifidelity_metrics.py`.

### Offline selected-episode video discretization

The offline video renderer consumes the immutable raw composition archive and
does not rerun the simulator, estimator, or controllers. Saved state index zero
is the pre-step initial state. For completed outer step $k\in\{0,\ldots,K-1\}$,
the displayed robot states are the saved arrays at index $k+1$, and the replay
time is

$$
\tau_k=\texttt{state\_times}[k+1].
$$

Let $s_r$ be `posterior_step` for saved posterior record $r$. The estimated
density frame uses the most recent causally available record

$$
r(k)=\max\{r:s_r\le k\},
\qquad
\widehat\phi_k=\texttt{posterior\_density}[r(k)].
$$

The hidden-truth video uses the episode's fixed `truth_density`. Both map
videos plot only the current aerial and ground positions; they do not infer or
draw trajectory trails. If the configured frame interval is $I$, the encoded
completed-step set is

$$
\mathcal F_I=
\bigl(\{0,I,2I,\ldots\}\cap\{0,\ldots,K-1\}\bigr)\cup\{K-1\},
$$

so the last saved completed state is always present. NRMSE, KL, and NLPD reuse
the equations above and add a point only at a saved posterior publication.
Their plot at frame $k$ contains exactly records with $s_r\le k$. The
locational-cost video evaluates every displayed post-step ground state using

$$
H_k=
\sum_j w_j\phi_j
\min_{i\in\{1,\ldots,N_g\}}
\lVert q_j-p^G_{i,k+1}\rVert^2.
$$

The effectiveness video evaluates the footprint-normalized coverage equation
below at every displayed post-step ground state, using the saved ground
headings and the archived resolved field of view and sensing range. Because
both $H_k$ and footprint-normalized effectiveness require $N_g>0$, the renderer
rejects a homogeneous aerial-only composition. Rendering and H.264 encoding
are offline observers with no feedback into any numerical state.

Implementation: `evaluation/render_multifidelity_episode_videos.py`.

For the four-method comparison replay, the proposed method uses the same
completed-step and latest-posterior alignment above. The density-comparison
video shows synchronized current robot positions for proposed MFGP-LR,
Egerstedt-LR, full-range Egerstedt, and standard Zhang in four panels. At
completed step $k$, the proposed panel displays
$\widehat\phi_{r(k)}$ from the latest causally available MFGP posterior, while
the three baseline panels display the single paired hidden density $\phi$.
Since only the proposed archive contains
`posterior_mean`, `posterior_variance`, and `posterior_density`, NRMSE, KL, and
NLPD remain proposed-MFGP metrics and are not imputed for oracle or distributed
baselines. At completed step $k$, the comparison videos reveal the already
evaluated arrays through saved state index $k+1$,

$$
\left\{\mathcal L^{(m)}_s,\mathcal E_s^{(m)}:
m\in\mathcal M_4,\ 0\le s\le k+1\right\},
$$

where $\mathcal L=H$ is the already implemented nearest-ground locational cost,
$\mathcal E=E_{\mathrm{cov}}$ is footprint-normalized effectiveness,
$\mathcal M_4$ is the ordered four-method set, and state index zero is the
shared initial condition. These histories are loaded from the paired evaluated
archive rather than recomputed during rendering. Implementation:
`evaluation/render_four_method_episode_videos.py`.

Two additional proposed-method spatial videos use the same causal posterior
index $r(k)$ and post-step robot state $k+1$. Their background fields are

$$
V_k=\texttt{posterior\_variance}[r(k)],
\qquad
\epsilon_k=\widehat\phi_{r(k)}-\phi.
$$

Thus robot positions advance on every encoded completed step, while $V_k$ and
$\epsilon_k$ remain held between asynchronous posterior publications. The
variance video's fixed episode-wide range is
$[0,\max_{r,j}\widehat\sigma^2_{H,r,j}]$. The signed-error video's fixed range
is $[-d_{\max},d_{\max}]$, where
$d_{\max}=\max_{r,j}|\widehat\phi_{r,j}-\phi_j|$. No trajectory trail is drawn
in either video.

The combined spatial-reconstruction video places $\phi$ and
$\widehat\phi_{r(k)}$ in its top-left and top-right panels, and $V_k$ and
$\epsilon_k$ in its bottom-left and bottom-right panels. All four panels use
the identical proposed aerial and ground positions at saved state $k+1$. The
top row shares the density normalization, and the bottom row reuses the fixed
variance and signed-error normalizations defined above.

The same four-method replay also writes four static companion images. With
$k_f=K-1$ and $r_f=r(k_f)$, their background fields are exactly

$$
\phi,
\qquad
\widehat\phi_{r_f}=\texttt{posterior\_density}[r_f],
\qquad
\widehat\sigma^2_{H,r_f}=\texttt{posterior\_variance}[r_f],
\qquad
\epsilon_{r_f}=\widehat\phi_{r_f}-\phi.
$$

The truth image contains only $\phi$. The latter three images overlay every
saved proposed-method aerial and ground position from state indices
$0,\ldots,K$, with starts and final positions marked separately. The truth and
estimated-density images use the shared normalization

$$
v_{\max}^{\phi}
=
\max\!\left(
\max_j\phi_j,
\max_{r,j}\widehat\phi_{r,j}
\right),
$$

matching the evolving comparison video's density scale. The variance image
uses $[0,\max_j\widehat\sigma^2_{H,r_f,j}]$ and does not transform, normalize,
or add sensor noise to the saved latent variance. The signed-difference image
uses the symmetric interval

$$
[-d_{\max},d_{\max}],
\qquad
d_{\max}=\max_j|\epsilon_{r_f,j}|,
$$

so equal-magnitude underestimation and overestimation have equal visual weight.
Density fields use `Reds`, variance uses `Greys` with larger variance darker,
and signed error uses `RdBu_r` with negative values blue and positive values
red. These colormap choices are presentation-only and do not transform the
saved numerical fields.

For the homogeneous-baseline replay, let
$\mathcal C_3=\{c_{\mathrm{het}},c_A,c_G\}$ contain the selected heterogeneous
composition and the unique equal-total-size aerial-only and ground-only
endpoints from the same composition archive. The renderer requires exact
equality of their seed, state-time vector, query grid, integration weights,
HIGH truth, truth density, free-space mask, and obstacle map. For each
$c\in\mathcal C_3$, the estimated-density panel at completed step $k$ uses its
own latest causal posterior

$$
r_c(k)=\max\{r:s_{c,r}\le k\},
\qquad
\widehat\phi_{c,k}=\texttt{posterior\_density}_{c,r_c(k)}.
$$

The synchronized truth panels use the validated common $\phi$. NRMSE, KL, and
NLPD are evaluated separately for every saved posterior of every composition
using the equations above. At video frame $k$, the live curve for composition
$c$ contains exactly the records $\{r:s_{c,r}\le k\}$; no value is interpolated
between asynchronous publications. Locational cost $\mathcal L$ and
footprint-normalized effectiveness $\mathcal E$ are intentionally absent
because both are undefined for the aerial-only endpoint. Frame subsampling,
post-step robot-state alignment, and final-frame inclusion use the same
$\mathcal F_I$ rule as the single-composition replay. Implementation:
`evaluation/render_homogeneous_baseline_episode_videos.py`.

## Implemented proposed-method parameter sensitivity study

The reviewer sensitivity pipeline is a one-factor-at-a-time experiment over
the proposed central MFGP only. Let $\boldsymbol\eta_0$ be the frozen reference
configuration and let $\eta_{f,l}$ be level $l$ of factor $f$. Every resolved
condition is

$$
\boldsymbol\eta_{f,l}
=
\boldsymbol\eta_0
\text{ with only factor }f\text{ replaced by level }l.
$$

The six implemented factors are environment dimensions, mixed aerial/ground
composition, step-count duration, circular-obstacle count/radius, paired
aerial/ground sensing range, and matched LOW/HIGH measurement-noise variance.
All factors require exactly one declared reference level. Episode $e$ uses the
same base seed $s_e=s_0+e$ at every level; a factor intentionally changes the
scenario arrays implied by that factor, while all other resolved inputs remain
equal apart from condition-identification metadata.

For active map dimensions $(H,W)$, the special full-environment range resolves
both sensor radii to

$$
R_A=R_G=R_{\mathrm{full}}=\sqrt{H^2+W^2}.
$$

This is at least the diagonal between any two admissible map coordinates. LOS
occlusion remains active, so `full_environment` removes the radial limit but
does not see through obstacles. For obstacle count $K_o$ and radius $R_o$, the
reported nominal density proxy is

$$
d_o=\frac{K_o\pi R_o^2}{HW},
$$

while the saved raster is authoritative for realized occupancy. For a mixed
composition $(N_A,N_G)$ and fixed active retention budget $B$, the implemented
caps are

$$
B_L=\max\!\left(1,\operatorname{round}
\left(B\frac{N_A}{N_A+N_G}\right)\right),
\qquad
B_H=\max(1,B-B_L).
$$

Every condition writes its own raw archive because map grids, team-state
shapes, and time axes may differ. Offline evaluation computes the existing
NRMSE, KL, marginal NLPD, calibration, footprint-normalized coverage, and
truth-weighted nearest-ground locational cost. Final and held-last-posterior
time-average reconstruction summaries are episode-level statistics. Factor
plots show episode points and deterministic episode-bootstrap 95% intervals;
no baseline archive is read or fabricated.

The combined absolute-metric overview uses a common ordinate and one panel per
factor. For the cross-factor effect plot, condition $l$ is paired with its own
factor reference by episode seed and reports

$$
\Delta m_{f,l,e}=m_{f,l,e}-m_{f,0,e}.
$$

The plotted point is the episode mean of $\Delta m_{f,l,e}$ and its interval is
the deterministic percentile interval from bootstrap resampling those paired
episode differences. Thus, for loss metrics such as KL divergence, a negative
effect means improvement relative to the reference. This visualization does
not pool time steps or compare unpaired episodes.

Implementations: `evaluation/multifidelity_parameter_sweep.py`,
`evaluation/run_multifidelity_parameter_sweep.py`, and
`evaluation/run_multifidelity_comparison.py` for proposed-method raw episodes;
`evaluation/plot_multifidelity_parameter_sweep_summary.py` for combined views.

## Implemented footprint-normalized coverage metric

The evaluation pipeline retains the raw hidden-truth mass visible through the
union of the ground robots' instantaneous sensing sectors,

$$
M_{\mathrm{vis}}(t)
=
\int_{\cup_i F_i(t)}\phi(q)\,dq.
$$

For $N_g$ ground robots with range $R$ and field-of-view angle $\theta$ in
radians, the nominal combined footprint-area budget is

$$
A_B
=
\min\left(A_{\mathrm{free}},\;N_g\frac{\theta R^2}{2}\right).
$$

The implemented discrete oracle sorts free query cells by decreasing truth
probability-density value $\phi_j$. It accumulates their integration weights
$w_j$ until area $A_B$ is reached and uses the required fraction of the final
cell. Equivalently, it computes

$$
M_\star(A_B)
=
\max_{0\le z_j\le 1}
\sum_j z_j\phi_jw_j,
\qquad
\sum_j z_jw_j\le A_B,
$$

with obstacle cells fixed to $z_j=0$. The reported footprint-normalized
coverage effectiveness is

$$
E_{\mathrm{cov}}(t)
=
\frac{M_{\mathrm{vis}}(t)}{M_\star(A_B)}.
$$

The denominator is fixed within an episode. Because it relaxes sector shape
and placement while preserving their nominal total area, it is an optimistic
upper bound: $E_{\mathrm{cov}}=1$ means the actual sectors capture the mass in
the densest free-space region of equal area. Actual-sector overlap, boundary
clipping, obstacles, and poor placement reduce only the numerator. The raw
$M_{\mathrm{vis}}$ is saved separately.

For the paired proposed-method/Egerstedt comparison, method $m$ uses its saved
ground states, field-of-view angle, and sensing range. The exact implemented
discrete numerator at saved state time $t_k$ is

$$
M_{\mathrm{vis},k}^{(m,e)}
=
\sum_j w_j\phi_j^{(e)}
\mathbf 1\!\left[q_j\in\bigcup_iF_{i,k}^{(m,e)}\right].
$$

The proposed method uses its saved headings to orient sectors. The Egerstedt
baseline has no heading state and declares a $360$-degree disk, making the
inserted zero headings immaterial. Each method receives its own equal-area
oracle $M_\star(A_B^{(m,e)})$ because the saved footprint geometries can differ.
The evaluator saves the final value and the trapezoidal time average

$$
\overline E_{\mathrm{cov}}^{(m,e)}
=
\frac{1}{t_K-t_0}
\sum_{k=0}^{K-1}
\frac{E_{\mathrm{cov},k}^{(m,e)}
+E_{\mathrm{cov},k+1}^{(m,e)}}{2}
(t_{k+1}-t_k).
$$

Runtime comparison uses the saved total wall-clock duration of each complete
method step. The evaluated archive stores the raw per-step totals and their
per-episode mean, median, empirical 95th percentile, and maximum. Runtime and
coverage are diagnostic outputs only and never feed back into either
controller. Implementations: `evaluation/multifidelity_metrics.py`,
`evaluation/evaluate_multifidelity_ablation.py`, and
`evaluation/evaluate_baseline_comparison.py`.

## Implemented standalone Zhang distributed coverage baseline

The standalone runner implements Algorithms 1 and 2 of Zhang et al. on the
paper's convex obstacle-free $3\times3$ domain. It is independent of the
multi-fidelity estimator and uses first-order point robots. The paper field is

$$
\phi(x,y)=
1.2e^{-(x+1)^2-(y+1)^2}
+1.2e^{-(x+1)^2-(y-1)^2}
+e^{-(x-1)^2-y^2}.
$$

The implementation forms $\phi_L$ and $\phi_H$ by rounding this field to the
configured low and high sensor resolutions. For aerial positions $p_i^A$ and
weights $w_i$, query point $q_j$ receives the stable, lowest-index assignment

$$
a(j)=\arg\min_i\left(\lVert q_j-p_i^A\rVert^2-w_i\right).
$$

Two aerial cells are neighbors exactly when their labels differ across a
horizontal or vertical raster face. With trapezoidal quadrature weights
$\omega_j$, the implemented low-field cell mass is

$$
s_i=\sum_{j:a(j)=i}\omega_j\phi_{L,j}.
$$

Algorithm 1 starts with $w_i=0$ and applies explicit Euler to the geometric
centroid controller until the configured tolerance or step cap:

$$
p_{i,k+1}^A=
\Pi_D\!\left[p_{i,k}^A+\Delta t\,g_1(C_{i,k}^{\rm geom}-p_{i,k}^A)\right].
$$

Let $l_i^0=n_i^0$ be the number of ground robots in cell $i$ after deployment,
$s_i^0$ its low-field mass, and $y_i^0=l_i^0/s_i^0$. Every discrete consensus
iteration snapshots all neighbor values. Each robot offers to one randomly
selected minimum-load neighbor when its own load is larger; each receiver
accepts one randomly selected maximum-load offer and transfers
$\lceil(l_r-l_i)/2\rceil$. Accepted transfers are applied simultaneously, so
$\sum_i l_i$ is invariant. The ratio update is

$$
y_i^{h+1}=y_i^h+
\frac{g_y}{s_i^0}
\sum_{r\in\mathcal N_i}(y_r^h-y_i^h),
\qquad
0<g_y<\min_i\frac{s_i^0}{|\mathcal N_i|}.
$$

After the configured fixed iteration count, the targets are
$\bar n_i=l_i$ and $\bar s_i=\bar n_i/y_i$. Seeded random tie resolution makes
repeated runs deterministic without introducing centralized state into any
robot's logical update.

During Algorithm 2, $\Delta s_i=\bar s_i-s_i$. The continuous paper laws are
$\dot w_i=g_w\Delta s_i$ and $\dot p_i^A=g_2\delta_i$. The code applies both
with explicit Euler and clips positions to the rectangular domain. For every
raster face $f$ separating cells $i$ and $r$, let $m_f$ be its midpoint,
$L_f\in\{\Delta x,\Delta y\}$ its length, and $\phi_{L,f}$ the average field at
its two incident query points. The exact implemented boundary quadrature is

$$
\widehat\delta_i=
\sum_{r\in\mathcal N_i}(\Delta s_i-\Delta s_r)
\sum_{f\in\partial V_{ir}}
\phi_{L,f}\frac{m_f-p_i^A}{\lVert p_i^A-p_r^A\rVert}L_f,
$$

$$
w_{i,k+1}=w_{i,k}+\Delta t\,g_w\Delta s_i,
\qquad
p_{i,k+1}^A=\Pi_D[p_{i,k}^A+\Delta t\,g_2\widehat\delta_i].
$$

Ground robot $r$ belongs to the power cell containing its position. Its local
cell $V_r^{\rm lim}$ is the intersection of that aerial cell, its ordinary
Voronoi cell among ground robots with the same parent, and its radius-$R_G$
sensing disk. Its high-field centroid uses only those selected grid points:

$$
C_r^{\rm lim}=
\frac{\sum_{j\in V_r^{\rm lim}}\omega_jq_j\phi_{H,j}}
{\sum_{j\in V_r^{\rm lim}}\omega_j\phi_{H,j}}.
$$

If robot $r$ is not selected for a neighbor-cell transfer, its update is

$$
p_{r,k+1}^G=
\Pi_D[p_{r,k}^G+\Delta t\,g_4(C_r^{\rm lim}-p_{r,k}^G)].
$$

For a load-balancing transfer from cell $i$ to neighbor $j$, the closest ground
robot $r^*$ to $p_j^A$ instead receives

$$
p_{r^*,k+1}^G=
\Pi_D[p_{r^*,k}^G+\Delta t\,g_3(p_j^A-p_{r^*,k}^G)].
$$

All commands use immutable same-step positions before simultaneous integration.
The saved locational diagnostic uses the nearest ground robot over the full
domain,

$$
H_k=\sum_j\omega_j\phi_{H,j}
\min_r\lVert q_j-p_{r,k}^G\rVert^2,
$$

and the saved travel diagnostic accumulates all ground displacements. The
default standalone experiment fixes `A5/G14` and sweeps $R_G$; configuration
may also declare multiple compositions, each satisfying $K>1$ and $N>K$.
Implementations: `evaluation/zhang.py`,
`evaluation/run_zhang_baseline.py`, and
`evaluation/plot_zhang_baseline.py`.

### Full-visibility Proposed--Rudolph--Zhang protocol

The dedicated full-visibility comparison resolves an obstacle-free shared
scenario before running any method. For map dimensions $(H,W)$ it sets both
proposed-method sensor radii and the Rudolph aerial/ground partition radii to

$$
R_A=R_G=R_{\mathrm{full}}\geq\sqrt{H^2+W^2},
\qquad \theta_A=\theta_G=2\pi.
$$

Consequently, no point is removed by a radial or angular visibility mask.
Standard Zhang retains its native full-cell information model. The proposed
method still collects its configured finite number of random observations per
sensor event: full visibility enlarges the admissible sampling domain but does
not turn one event into a dense observation of every grid cell. Rudolph uses
oracle truth density as already documented for that baseline.

The shared archive fixes seeds, hidden fields, initial states, grid, and mission
clock for all three methods. Zhang's deployment consumes this common clock.
Since every 360-degree ground footprint covers the whole domain,
$M_{\mathrm{vis}}(t)=1$ and footprint-normalized coverage is identically one
up to numerical quadrature; it is therefore non-discriminative here. The
nearest-ground locational cost, travel, and timing remain meaningful common
metrics. Implementation:
`evaluation/run_full_visibility_comparison_pipeline.py`.

### Paired Zhang mission-clock implementation

The paired three-method runner uses the same core equations but does not execute
deployment before its saved clock. Let the shared physical horizon be
$T=K\Delta t=30$ s. Physical square coordinates with lower corner $o$ and side
length $L$ are mapped into the paper-scale square by

$$
\widetilde q=\frac{3}{L}(q-o)-\begin{bmatrix}1.5\\1.5\end{bmatrix}.
$$

Commands are evaluated in $\widetilde q$ coordinates and mapped back before
archiving. The paired ground sensing radius is transformed by the same isotropic
factor $3/L$.

At each deployment state, define the raster centroid residual

$$
e_k^A=\max_i\lVert C_{i,k}^{\mathrm{geom}}-p_{i,k}^A\rVert.
$$

The implemented transition time is the first saved physical time satisfying the
configured sub-grid tolerance $\varepsilon_A$,

$$
\tau=\inf\{t_k:e_k^A\le\varepsilon_A\}.
$$

Before this transition, only the aerial deployment law is integrated and every
ground position is held exactly constant:

$$
p_{r,k+1}^G=p_{r,k}^G,
\qquad t_{k+1}\le\tau.
$$

Target load and mass consensus executes at $\tau$. Because the paper assigns no
physical duration to one consensus round, these iterations do not advance
simulation time; their wall-clock duration is included in the corresponding
controller-step runtime. Algorithm 2 starts after the transition and stops at
the unchanged deadline $T$. If the transition set is empty before $T$, $\tau$
is saved as `NaN`, target values remain unavailable, and the ground team remains
stationary for the complete evaluated episode.

For paired fields whose scale changes between episodes, the realized consensus
gain is selected as a declared fraction $\eta\in(0,1)$ of the theorem's local
stability bound,

$$
g_y=\eta\min_i\frac{s_i^0}{|\mathcal N_i|}.
$$

The current comparison uses $\eta=0.5$. Implementations:
`evaluation/run_zhang_comparison.py`,
`evaluation/evaluate_three_method_comparison.py`, and
`evaluation/run_baseline_comparison_pipeline.py`.

### Opt-in Zhang-LR finite-aerial-range extension

The original Zhang comparison above retains the paper assumption that the
aerial sensing radius is sufficiently large and therefore integrates every
complete power cell. The separately labelled Zhang-LR stress-test mode instead
uses the finite aerial radius $R_A$ saved by the paired proposed-method
scenario. Define

$$
B_i^A(k)=\{q:\lVert q-p_{i,k}^A\rVert\le R_A\},
\qquad
\widetilde V_i^A(k)=V_i^A(k)\cap B_i^A(k).
$$

Algorithm 1 geometric deployment is unchanged because its centroid depends
only on power-cell geometry, not sensed scalar-field values. Once field masses
are required, Zhang-LR uses the exact raster quantity

$$
\widetilde s_{i,k}
=\sum_{j:a_k(j)=i}
\omega_j\phi_{L,j}
\mathbf 1[\lVert q_j-p_{i,k}^A\rVert\le R_A]
$$

in target allocation, mass error, and weight updates. In the raster boundary
quadrature for aerial robot $i$, a face midpoint contributes only when it lies
inside $B_i^A(k)$. Visibility is evaluated independently for the two robots on
a shared face, so a face may contribute to one command but not the other.

The archived geometric support diagnostic is

$$
\chi_{i,k}^A=
\frac{\sum_{j:a_k(j)=i}\omega_j
\mathbf 1[\lVert q_j-p_{i,k}^A\rVert\le R_A]}
{\sum_{j:a_k(j)=i}\omega_j}.
$$

Thus $\chi_{i,k}^A=1$ means the saved disk covers the complete rasterized power
cell. Ground sensing, ground centroids, mission timing, consensus, and
geometric deployment are unchanged. This finite-range law is an explicit
extension for an out-of-assumption stress test; it is not attributed to the
original Zhang paper. `algorithm.aerial_sensing_mode: full_cell` selects the
paper baseline, while `limited` selects Zhang-LR. Implementation:
`evaluation/zhang.py` and `evaluation/run_zhang_comparison.py`.

### Direct paired standard-versus-LR diagnostics

The direct evaluator accepts the two result archives only when their scenario
fingerprints and all scenario-contract arrays are exactly equal. For aerial
robot $i$ and ground robot $r$, the saved per-state trajectory differences are

$$
d^A_{i,k}=\lVert p^{A,\mathrm{standard}}_{i,k}
-p^{A,\mathrm{LR}}_{i,k}\rVert_2,
\qquad
d^G_{r,k}=\lVert p^{G,\mathrm{standard}}_{r,k}
-p^{G,\mathrm{LR}}_{r,k}\rVert_2.
$$

For class $C\in\{A,G\}$, its first-divergence time uses the exact implemented
numerical threshold $\epsilon_d=10^{-10}$,

$$
t^C_{\mathrm{div}}
=\min\{t_k:\max_i d^C_{i,k}>\epsilon_d\},
$$

and is stored as `NaN` if the set is empty. The evaluator also stacks the
standard full-cell support $\chi^A_{i,k}=1$ beside the Zhang-LR support defined
above, target masses and loads, footprint-normalized ground coverage, the
nearest-ground locational cost $H_k$, and cumulative class-specific travel.
Final values use $t_K=30$ s; time averages use trapezoidal integration over the
complete mission clock. Implementations:
`evaluation/evaluate_zhang_variant_comparison.py`,
`evaluation/plot_zhang_variant_comparison.py`, and
`evaluation/run_zhang_variant_comparison.py`.

## Implemented Egerstedt comparison baseline

The separate baseline runner uses the saved obstacle-free scenario and the
control functions in `evaluation/egerstedt.py`. It assumes the hidden truth
$\phi_j$ is known. At each discrete time $k$, aerial robot $a$ is assigned the
range-limited Euclidean Voronoi set $V^A_a$ and moves toward its unweighted
grid centroid $c^A_a$:

$$
p^A_{a,k+1}=p^A_{a,k}+\Delta t\,0.5(c^A_{a,k}-p^A_{a,k}).
$$

Ground robot $i$ similarly computes the truth-density-weighted centroid
$c^G_i$ of its range-limited Voronoi set. Ground robots are also assigned to
their nearest aerial robot. For aerial cell $a$, the implemented allocation
error and threshold are

$$
\sigma_a=\frac{n_a}{N_g}
-\frac{\sum_{j\in V^A_a}\phi_j}{\sum_j\phi_j},
\qquad
\widehat\sigma_a=
\begin{cases}
\sigma_a,&\sigma_a>1/N_g,\\
0,&\text{otherwise}.
\end{cases}
$$

Let $a^- = \arg\min_a\sigma_a$. If ground robot $i$ belongs to aerial cell
$a(i)$, its point position is updated by

$$
p^G_{i,k+1}=p^G_{i,k}+\Delta t\left[
(1-\widehat\sigma_{a(i)})(c^G_{i,k}-p^G_{i,k})
+\widehat\sigma_{a(i)}(c^A_{a^-,k}-p^G_{i,k})
\right].
$$

The runner uses the paired mission timestep $\Delta t$, clips ground positions
to the rectangular domain, and rejects maps containing obstacles. Both robot
classes are first-order point robots with omnidirectional range-limited sensing
in this baseline; no heading state is invented. Its stored locational cost is

$$
H_k=\Delta A\sum_j\phi_j
\left\|q_j-p^G_{\operatorname{Vor}(j),k}\right\|^2.
$$

This cost is a baseline diagnostic, not the common comparison coverage metric.
The baseline has oracle access to $\phi$ and therefore does not produce a
reconstructed density or posterior uncertainty.

### Egerstedt range override and final four-condition protocol

Let $R_A^{\mathrm{sc}}=10$ be the aerial range stored in the immutable proposed
scenario. The Egerstedt runner uses the effective controller radius

$$
R_A^{\mathrm{eff}}=
\begin{cases}
R_A^{\mathrm{sc}},&\text{when no override is supplied},\\
R_A^{\mathrm{override}},&\text{otherwise}.
\end{cases}
$$

The limited condition uses $R_A^{\mathrm{eff}}=10$. On a query rectangle with
coordinate extrema $(x_{\min},x_{\max},y_{\min},y_{\max})$, an override is
classified as full-domain only when

$$
R_A^{\mathrm{eff}}\ge
d_D=\sqrt{(x_{\max}-x_{\min})^2+(y_{\max}-y_{\min})^2}.
$$

The implemented publication condition uses $R_A^{\mathrm{eff}}=75$. The
scenario-contract array `aerial_sensing_range` remains 10 in both Egerstedt
archives, and `effective_aerial_sensing_range` stores the controller-specific
value. Thus the scenario fingerprint remains identical across proposed,
Egerstedt-LR, full-range Egerstedt, and standard full-cell Zhang.

For metric history $M_{m,e,k}$, method $m$, episode $e$, and state $k$, each
bootstrap replicate draws one episode-index vector $I_b$ shared by all four
methods and computes

$$
\overline M^{(b)}_{m,k}
=\frac{1}{E}\sum_{e=1}^{E}M_{m,I_b(e),k}.
$$

The pointwise 95% confidence band is the 2.5th and 97.5th percentile of
$\overline M^{(b)}_{m,k}$ over the configured 2000 deterministic replicates.
The final plot applies this operation only to the footprint-normalized coverage
defined above and to the common nearest-ground locational cost $H_k$. Final
values use state $K$; time averages use trapezoidal integration over the full
30-second mission. Implementations:
`evaluation/run_egerstedt_comparison.py`,
`evaluation/evaluate_four_method_comparison.py`,
`evaluation/plot_four_method_comparison.py`,

# Shared-reference registration of aligned local frames

The standalone deployment registration helper assumes aligned horizontal NED
axes and simultaneous, finite local positions $p_i$ and shared-reference
positions $g_i$. For reference vehicle $r$, it computes

$$
t_i=(g_i-g_r)-(p_i-p_r),\qquad p_i^{\mathrm{common}}=p_i+t_i,
\qquad p_i=p_i^{\mathrm{common}}-t_i.
$$

Thus $t_r=0$. `src/core/common_frame.py` implements this translation using one
snapshot per vehicle; it does not estimate alignment, timestamps, uncertainty,
frame resets, or reference quality. Adapters must validate those assumptions.
This helper is not yet integrated into the simulator or a deployment service.

`src/core/global_reference.py` supplies a separate WGS84 local tangent
projection. For latitude $\phi$, longitude $\lambda$, ellipsoidal height $h$,
semi-major axis $a=6378137$ m and squared eccentricity
$e^2=0.0066943799901413165$, let $N=a/\sqrt{1-e^2\sin^2\phi}$ and
$X=((N+h)\cos\phi\cos\lambda,(N+h)\cos\phi\sin\lambda,
(N(1-e^2)+h)\sin\phi)$. The returned coordinates are the dot products of
$X-X_r$ with the reference-frame north vector
$(-\sin\phi_r\cos\lambda_r,-\sin\phi_r\sin\lambda_r,\cos\phi_r)$ and east
vector $(-\sin\lambda_r,\cos\lambda_r,0)$. It accepts ellipsoidal heights;
MULLET heartbeat altitude is documented as mean sea level and cannot be
silently substituted. This helper neither synchronizes nor validates a global
position source; the ROS frame registry uses it to supply deployment agents.

`src/core/registration_readiness.py` additionally checks an indexed window of
pre-synchronized paired positions. Each vehicle has the same count $K\ge2$;
timestamps strictly increase, lie in $[t_{now}-A,t_{now}]$, and across-vehicle
timestamp range at each index does not exceed $S$. For both local and shared
positions, each sample must lie within distance $D$ of its own window mean.
The helper registers the two means with the equation above and records each
vehicle's unchanged horizontal reset counter. A counter change invalidates a
subsequent match. The caller is responsible for paired-source synchronization,
clock domains, axis alignment, absolute localization accuracy and reset-counter
validity; stationarity is not an accuracy guarantee.

## Prototype unicycle circular-obstacle CBF speed filter

For a unicycle with position $p$, heading $\theta$, and signed speed $v$, let
$e=(\cos\theta,\sin\theta)$ and inflated circle $i$ have center $c_i$ and
radius $R_i>0$. The prototype in `src/core/unicycle_cbf.py` defines
$h_i=\|p-c_i\|^2-R_i^2$ and enforces the instantaneous continuous-time
inequalities

$$
2(p-c_i)^\top e\,v\ge-\alpha h_i,\qquad -v_{max}\le v\le v_{max}.
$$

It intersects these scalar half-spaces and clips the nominal speed into the
resulting interval, or reports infeasibility without returning a speed. For
coefficients of absolute value at most $10^{-12}$ it treats the coefficient as
zero. Heading commands, boundaries, inter-robot separation, discretization,
tracking and uncertainty are not handled. This standalone prototype is not
integrated into the simulator and provides no discrete-time or flight safety
guarantee; the existing ground controller remains unchanged.

The optional standalone `guard_unicycle_step` models the repository's
heading-first integrator with $d=v\Delta t(\cos(\theta+\omega\Delta t),
\sin(\theta+\omega\Delta t))$. For each circle it projects its center onto
the closed segment $p+sd$, $s\in[0,1]$. A segment touching an inflated circle
suppresses translation; a starting point inside or on a circle reports
infeasibility. It does not handle map boundaries or physical tracking, and is
not integrated with any controller. The continuous CBF condition alone can
permit a discrete-time obstacle crossing when a command is held too long.

The limited offline pilot `evaluation/obstacle_policy_pilot.py` measures minimum
sampled circular clearance $\min_k(\|p_k-c\|-R)$, terminal distance
$\|p_K-p_{goal}\|$, and the number of executed speeds below $10^{-3}$ in
absolute value. It uses the existing raster guard for both policies, adds the
existing bounded repulsion for one, and applies the prototype circular CBF and
segment guard for the other. These point-sampled metrics do not establish
continuous clearance, coverage performance, or physical flight safety.

## Deployment field-service sampling

The standalone `src/core/deployment_field_service.py` maps a metric sample
request position $p$ to grid coordinates $u=(p-o)/r$ using origin $o$ and
positive resolution $r$. It invokes the existing seeded area-uniform sector
sensor with range divided by $r$; accepted grid positions $u_s$ become map
positions $p_s=o+ru_s$. The existing sensor samples the nearest rounded raster
cell and adds configured Gaussian noise. HIGH or LOW field selection and
optional raster line-of-sight are per sensor. An unoccluded 360-degree sensor
represents the high-altitude footprint. Identical per-vehicle request IDs and
payloads replay the same cached observations; conflicting duplicates and cache
overflow are rejected. The deployment runtime connects this in-memory component to scenario loading,
central estimator submission and the ROS wrapper; clock validation and
physical-flight validation remain separate responsibilities.

The standalone manifest builder `src/core/deployment_scenario.py` defines the
HIGH raster at grid center $q$ as $\sum_j a_j\exp(-\|q-c_j\|^2/(2s_j^2))$.
A raster cell is occupied when its center is within a declared circular
obstacle. It applies `build_fidelity_fields` to the entire HIGH raster without
masking obstacles, so the unoccluded LOW sensor can sample over virtual
obstacles; HIGH visibility uses the occupancy raster. It hashes the canonical
JSON form of the supplied manifest, including placeholder settings. This is not
a resolved configuration or asset-hash protocol, nor flight-readiness validation.

The standalone `src/core/deployment_estimator.py` constructs the existing
central MFGP on an evenly spaced map grid with product trapezoidal integration
weights, without an obstacle density mask. Batch submission queues existing
`Observation` values; a due update at time $t$ invokes the existing central
estimator at most once and sets the next eligible time to $t+T$, rather than
catching up missed periods. A due update is rejected while pending observations
have timestamps later than $t$. Existing GP fitting and posterior publication
equations and failure preservation remain unchanged. These are sequential
in-memory semantics, not a clock synchronization or ROS transport guarantee.
The adapter's `aerial_target` delegates to the existing `build_aerial_target`
using posterior density and variance with default interest weight $1$ and
uncertainty weight $0.25$. It does not yet drive a coverage controller.

The ROS agent sampling path schedules requests at the sensor period specified
in the manifest. With a currently published offset $t_i$ it transforms heartbeat local
position $p_i$ to $p_i+t_i$, preserving heading under the assumed aligned axes.
It sends only when the heartbeat is valid, armed, not landed, in HOLD or
MISSION, and $0\le t_{now}-t_{heartbeat}\le1$ second; the central status hash
must match the local manifest. The offset, shared clock, heading alignment and
frame-reset validity are not established by this sampling gate. Command
publication is a separate, explicitly enabled path described below.

`docker/deployment_frame_registry.py` estimates $t_i$ from paired heartbeat
snapshots using the aligned-frame equation above, with latitude/longitude
projected onto the WGS84 ellipsoid at zero height for both vehicles. It accepts
successive pairs within 0.25 s timestamp skew, each at most 2 s old, and
requires five pairs whose offset estimates and both local-position windows
deviate no more than 0.3 m from their respective means. The accepted offset is
the mean of the five estimates. A relative inconsistency exceeding 1 m clears
the affected offset; a reference inconsistency exceeding 1 m, reference
heartbeat sequence restart, or reference localization loss after initialization
latches all registration off until a full deployment restart. The
registry publishes currently fresh offsets every 0.25 s with a 0.75 s expiry;
agents discard missing, mismatched, or expired offsets. This is a 2D
approximation using heartbeat snapshot timestamps, not a verified measure of
global-position accuracy or synchronization, and it does not detect every
local-origin reset.

`docker/deployment_hedac_planner.py` provides an experimental aerial
adapter. It maps metric position to an obstacle-free planner grid by
$u=(p-o)/r$, updates the existing HEDAC coverage at that measured position,
normalizes the supplied target with the existing HEDAC validator, advances the
existing heat discretization a fixed 40 times per call by default, and returns
$v=v_{max}\nabla h/\|\nabla h\|$ using the existing HEDAC gradient routine
(zero gradient yields zero velocity). It does not integrate or command a vehicle,
and its default parameters and update rate are not flight-validated.

The onboard aerial agent calls this adapter every $0.5$ seconds when
both a map pose and posterior target have matching scenario identity and ages
between zero and two seconds. It requires an evenly spaced square grid,
uses the configured aerial role speed limit, and publishes a proposed velocity
with an expiry two seconds later. It does not send MULLET commands. The pose
agent publishes its existing validated sampling pose separately for this path;
this does not establish frame-registration or clock correctness.

`docker/deployment_ground_planner.py` implements proposal-only weighted
Voronoi coverage. Each query point $q_j$ is assigned to the closest ground-role
position (ties go to the first vehicle); for weights $w_j$ and HIGH density
$\rho_j$, cell $i$ has centroid $c_i=\sum_{j\in V_i}w_j\rho_jq_j/\sum_{j\in V_i}w_j\rho_j$,
or its current position when the mass is at most machine epsilon. With
distance $d_i=\|c_i-p_i\|$ and heading error $\theta_i^*-\theta_i$, the
proposed signed speed is $\operatorname{clip}(k d_i\cos(\theta_i^*-\theta_i),-v_{max},v_{max})$;
the map-frame velocity is that speed times $(\cos\theta_i,\sin\theta_i)$.
Each onboard ground planner requires all configured ground poses and the HIGH
posterior to be at most two seconds old and runs every 0.5 seconds with
$k=1$ and the configured ground role speed limit. These are proposals only, with no obstacle
repulsion, safety filter, heading-rate controller or MULLET command output.

## Fixed-duration SITL mission and command lease

`docker/timed_mission.py` and `docker/ros_timed_mission.py` define an explicit
mission scheduler. After three ready checks at 0.5 s intervals, all configured
agents must be command-enabled, lease-required and in HOLD, with available
MULLET start/hold services and a single mission-lease publisher. Let $s$ be
monotonic wall time, $s_0$ the first start-request time, and $T>0$ the requested
duration. The common deadline is

$$
s_{end}=s_0+T.
$$

At $s\ge s_{end}$ the runner disables its lease and requests HOLD from every
vehicle. A start rejection/timeout, cancellation or unhealthy running pipeline
also requests HOLD for the whole team. The running-health check has a two-second
startup grace. Default start/hold service timeouts are 5 s. The deadline covers
startup-service latency; it is not measured from the final start acknowledgement.
HOLD request/response times and fresh reported HOLD states are recorded; they
do not establish instantaneous physical stopping.

While starting/running, `docker/ros_timed_mission.py` renews a ROS-clock lease
every 0.1 s with expiry $L=t+0.5$ s. `docker/mission_lease.py` accepts matching
scenario/vehicle leases only when $t_{creation}\le t<L$ and their stated lifetime
does not exceed 0.75 s. When `control.require_mission_lease` is true (the default
SITL scenario), `docker/deployment_command_gate.py` adds the condition $t<L$ to
command acceptance. The runner revokes the lease before HOLD requests, and a
lost runner stops renewing it; command loss then invokes MULLET's own timeout
behavior. Takeoff and landing remain external. The runner records before,
during and after its command phase using the existing readiness recorder.

### Paper-based filtering with a shared HIGH objective and sample budget

The source is Mantovani, Pratissoli and Sabattini, *Distributed Coverage Control
for Spatial Processes Estimation With Noisy Observations*, IEEE RA-L 9(5),
4431–4438 (2024), DOI 10.1109/LRA.2024.3381809, Section VI, Algorithm 1,
Eqs. (18)–(19). The repository PDF is
[the paper](biblio/Distributed_Coverage_Control_for_Spatial_Processes_Estimation_With_Noisy_Observations.pdf).
The paper treats distributed single-fidelity GPs. Its rule is
$$
\epsilon=e(\mu_{max}-\mu_{min}),\qquad
\sigma_{\mathrm{ep}}(x)\ge\epsilon/z,
$$
with $e=0.05$, $z=1.96$. This uses **latent standard deviation**, excluding
additive measurement-noise variance. The optional `native_epistemic` criterion
implements this rule with each observation's native LOW or HIGH latent GP.

**Implemented active multi-fidelity extension.** The central estimator and
single posterior remain shared. `criterion: high_information` uses one HIGH
field objective and one threshold for both input fidelities:
$$
\tau_H=\frac{e}{z}\left(\max_{q\in G}\mu_H(q)-\min_{q\in G}\mu_H(q)\right).
$$
Here $G$ is the configured query grid (masked if a mask is supplied). The range
uses the last committed **raw HIGH mean**, without density normalization,
clipping or access to ground truth. The threshold stays fixed within one
scheduled update. An initially flat mean gives zero threshold; bootstrap
accepts samples with positive information, subject to the budget.

For a candidate observation $y_f(x)=f_f(x)+\nu_f$, $f\in\{L,H\}$, denote
current latent conditional covariance by $C_{ab}$. With known observation noise
variance $r_f$ and the model's effective jitter $\eta$, its expected reduction
of HIGH variance **at that candidate's location** is
$$
\Delta V_H(x;y_f)=
\frac{C_{Hf}(x,x)^2}{C_{ff}(x,x)+r_f+\eta},\qquad
s_f(x)=\sqrt{\Delta V_H(x;y_f)}.
$$
The candidate passes the information test iff $s_f(x)>0$ and $s_f(x)\ge\tau_H$.
This is a local expected-variance-reduction criterion, not integrated global
information gain. It is an explicit extension, not a claim that the paper uses
this equation. Both fidelities share the same HIGH-unit threshold. Measurement
noise is never added to epistemic variance; it correctly attenuates the
expected reduction through the observation denominator. If LOW has no HIGH
cross-covariance (e.g. $\rho=0$), LOW cannot pass merely because discrepancy
variance is high.

**Exact mixed posterior and sequential batch equations.**
`MultiFidelityGaussianProcess.predict_joint_latent` evaluates arbitrary LOW/HIGH
latent variables. For flags $h_i\in\{0,1\}$ and $a_i=1$ for LOW or
$a_i=\rho$ for HIGH,
$$
K_{ij}=a_i a_j k_L(x_i,x_j)+h_i h_j k_\delta(x_i,x_j),\qquad
C=K-K_{DY}^{\mathsf T}A^{-1}K_{DY}.
$$
$A$ is the existing retained training covariance including individual noise
variances and jitter. All products with $A^{-1}$ are implemented using the
existing Cholesky factor and triangular solves, never explicit inversion.
`predict_low` exposes native LOW marginals while `predict_high` retains its
existing API and equations.

For pending observations $Y=(y_{f_j}(x_j))$, the filter computes the latent
candidate covariance $C_{YY}$ and $B_{ij}=C_{Hf_j}(x_i,x_j)$ from the committed
model. Candidates are processed by timestamp and stable pending index (LOW
before HIGH for equal timestamps across the two buffer lists). After accepting
candidate $j$, let $d=C_{YY,jj}+r_j+\eta$. Rank-one conditioning uses
$$
C_{YY}\leftarrow C_{YY}-\frac{C_{YY,:,j}C_{YY,:,j}^{\mathsf T}}{d},\qquad
B\leftarrow B-\frac{B_{:,j}C_{YY,:,j}^{\mathsf T}}{d},
$$
with both right-hand-side columns copied **before** either update. Later
candidates therefore account for earlier accepted measurements without fitting
or optimizing a separate GP per observation. Observed values affect the fitted
posterior after admission, not this within-batch covariance update. Exact
observation-record duplicates are skipped; new noisy observations at the same
position can remain informative.

**Shared budget and transaction semantics.** Active configuration is
`max_total_samples: 1000`, increased from the first shared $B=500$
configuration, and below the temporary $1000+1000$ per-fidelity limits:
$$
|D_L|+|D_H|\le B=1000.
$$
There is no active per-fidelity quota: either fidelity may occupy all $B$
slots. The internal per-fidelity buffers each allow $B$ entries solely to
accommodate any split; the common admission step enforces the combined cap.
The historical/default `on_full: reject` mode never evicts admitted data; if no
slot remains, new candidates are counted as capacity-rejected. The active
`on_full: information` mode additionally permits improving replacements as
specified below. This hard cap is an additional
engineering constraint, absent from the paper, and can halt learning of new
regions after saturation. It is not a guarantee of maintaining useful coverage
everywhere with a finite number of observations. Optional separate caps remain available
for historical/native-filter configurations; mixing both budget formats is
rejected. Default/legacy estimator settings keep newest-first retention.

`BoundedObservationBuffer.candidate(pending_admission=...)` builds candidates
without mutating retained or pending observations. A successful fit commits
both buffers and filter counters together. Filter/fit failure preserves the
previous valid GP, snapshot, counters and pending observations for retry.
If all candidates are rejected, pending records are consumed without refitting
or incrementing the posterior version. No optimization occurs at command rate.

**Publication and code map.** At scheduled central ticks, a filtered static
model with no informative new data still publishes its current valid arrays.
In the pure runtime `timestamp` initially records tick start; the ROS
publication loop restamps it at actual emission (before compute for a cached
heartbeat and after compute for a completed result). `posterior_timestamp` is
the immutable last-fit snapshot timestamp; `model_updated` distinguishes fits
from refreshes. A refresh changes no posterior arrays/version and does not mean a
new observation or new GP fit occurred. Failed updates do not refresh the
target. This prevents intentional redundancy rejection from being mistaken for
a missing central publisher, while preserving pose/lease/command freshness.
The static-field assumption is essential; no temporal field dynamics are added.

### Information-based replacement at the shared capacity (2026-11-04)

The active scenario keeps $B=1000$ and adds `on_full: information` with
`replacement_min_improvement: 1e-8`. Historical manifests without that setting
continue using `on_full: reject`. Replacement requires enabled HIGH-information
filtering and a shared budget. It does not change the MFGP model or the paper's
admission threshold; this bounded replacement step is a further extension of
the paper, not an algorithm attributed to it.

**Implemented objective and scope.** For the configured query points $G$,
integration weights $w_q$ and optional mask $m_q$, define
$$
\bar w_q=\frac{w_q m_q}{\sum_{u\in G}w_u m_u},\qquad
J(D)=\sum_{q\in G}\bar w_q\operatorname{Var}[f_H(q)\mid D].
$$
With no mask, $m_q=1$. Weights are fixed integration weights, not estimated
coverage density or hidden truth. This is a finite-grid average, not a
continuous-domain guarantee. Lower $J$ does not imply lower true estimation
error or lower variance at every query point.

When an update starts with a full retained set, the existing filter first
identifies informative pending candidates that would otherwise be rejected
for capacity. The estimator scores **all** pairs of one such new sample and
one retained sample, chooses the best improving pair, and permits **at most
one swap per scheduled update**. Ordinary admission handles updates that start
below capacity; no replacement is attempted in the same update that first
fills it. This bounds the work and guarantees at most one final joint-GP fit.
No age-based or fidelity-based replacement priority is imposed. A nearby HIGH
sample can replace LOW data if the weighted HIGH objective improves; the best
removal may also be spatially distant if those data are more redundant.

**Exact addition/removal scores at fixed model parameters.** Let $A$ be the
current retained noisy covariance (including jitter), $L$ its Cholesky factor,
$k(q)=\operatorname{Cov}(D,f_H(q))$ and $c=\operatorname{Cov}(D,y_{new})$.
Set
$$
a=A^{-1}c,\quad U_j(q)=[A^{-1}k(q)]_j,\quad
p_j=e_j^{\mathsf T}A^{-1}e_j,\quad
b(q)=\operatorname{Cov}(f_H(q),y_{new}\mid D),
$$
$$
d=\operatorname{Var}(f_{new}(x)\mid D)+r_{new}+\eta,
\qquad g=\frac{\sum_q\bar w_q b(q)^2}{d}.
$$
Here $r_{new}$ is the candidate's known noise variance and $\eta$ is the
current effective jitter. Adding the candidate reduces $J$ by $g$. The
subsequent increase from removing old sample $j$ from that augmented model is
$$
\ell_j^+=\frac{\sum_q\bar w_q
\left[U_j(q)-\frac{a_j}{d}b(q)\right]^2}
{p_j+a_j^2/d},\qquad
\Delta J_j=g-\ell_j^+.
$$
These scores equal $J(D)-J((D\setminus\{j\})\cup\{new\})$ at fixed
kernels and noise. `MultiFidelityGaussianProcess.score_replacements` evaluates
them by triangular solves against $L$ and $L^{\mathsf T}$. No explicit
inverse matrix is formed. The diagonal $p_j$ is obtained from squared norms
of blocked solves $LZ=E$ for at most 64 basis columns at a time, rather than
storing a full precision matrix. Matrix products reuse the current factor to
score the entire retained/candidate pairing; no trial GP is fitted per pair.
Rows follow retained LOW-then-HIGH order; pending candidates follow timestamp
and stable admission order. Equal-score ties use the first matrix entry.

**Selection and final verification.** The required improvement is
$$
\delta_{min}=\max\left(\texttt{replacement\_min\_improvement},
10^{-12}\max(1,|J(D)|)\right).
$$
A proposed swap must satisfy $\Delta J>\delta_{min}$. After fitting the
proposed dataset, the actual published-grid variance must also satisfy
$J(D_{swap})<J(D)-\delta_{min}$. If this final check fails, old observations
and posterior are kept and pending candidates are consumed as rejected. A
filter/scoring/fit/normalization exception instead preserves pending data too,
allowing retry. The active deployment uses fixed kernels; the final check also
protects the objective if optional optimization or adaptive jitter changes the
model from that assumed by the analytic scores.

`BoundedObservationBuffer.candidate` now accepts `retained_admission` alongside
`pending_admission`. Both masks are staged, with no mutation until the entire
new posterior validates. Admission/removal and counters commit together, keeping
$|D_L|+|D_H|\le1000$. With one replacement the size remains constant. Rejected
swaps do not increment the posterior version. Existing static refresh semantics
apply when there is no new committed fit.

**Diagnostics and readiness.** `sample_filter` exposes cumulative `replaced`,
`evicted_low`, `evicted_high`, and `replacement_evaluations` (number of pair
scores), plus the last verified $J$ before/after and its improvement. Existing
accepted counters count historical admissions, not currently retained samples.
The readiness checker in shared replacement mode requires both fidelities to
have contributed (current retained data or committed historical admissions),
a nonempty retained model and current valid posterior. It does not impose a
permanent fidelity quota that could falsely fail when the last LOW or HIGH
sample is replaced. All timestamp, command, frame, pose and lease checks remain.

### Sequential central compute/publication timing correction (2026-11-04)

The failed `mission_filtered` run stopped at 129.949 s: after the budget filled,
a replacement took about 1.45 s and completion-only publications were 2.49 s
apart. The 2 s target age gate cleared all plans, and the 0.25 s observed-command
gate caused HOLD. This was not a GP numerical failure. The old Docker image
used generic system BLAS (NumPy 1.26.4 / SciPy 1.11.4); the image now explicitly
installs NumPy 1.26.4 / SciPy 1.13.1 binary wheels with OpenBLAS and one thread.
This changes the numerical implementation/performance, not the GP equations.

**Deployed schedule.** `docker/deployment_publication.py::CentralUpdateLoop`
is a normal sequential object owned by the central ROS node. Let $s_k$ be ROS
clock time at attempt start, $c_k$ its completion time, and $T$ the configured
update period (1 s). The ROS integration calls
`DeploymentEstimator.complete_update(c_k)` so the next attempt satisfies
$$
s_{k+1}\ge c_k+T.
$$
The existing 0.1 s polling timer can add dispatch delay. There is no catch-up
burst when compute exceeds the nominal period. The pure adapter's explicit-time
`update` API remains available for deterministic offline experiments; the
completion rule is applied by the deployed publication loop.

If a valid cached posterior exists and the preceding attempt has not failed,
the loop publishes it at $s_k$ with `model_updated=false` and
`update_in_progress=true`. It also publishes current central status before
compute. After a successful attempt it publishes the new or unchanged valid
posterior at $c_k$, with `update_in_progress=false`. Both target packets use
actual emission timestamps rather than subtracting compute time from their
freshness. `posterior_timestamp` and version change only after an actual fit;
`update_started_at`, `update_completed_at` and monotonic `update_duration_s`
report computation separately. The completed packet's timestamp is not a claim
that its observations were acquired at completion time.

For attempt duration $D_k=c_k-s_k$ and idle interval approximately $T$, the
ideal maximum gap from this before/after pattern is approximately
$\max(T,D_k)$ rather than $T+D_k$ for completion-only publication. ROS scheduling
and serialization can add delay; this is not an unbounded deadline guarantee.
No target (2 s), central-status (2 s), pose, lease or command limit is increased.
A known failed attempt suppresses later cached refreshes until recovery. A
pre-update heartbeat may have been emitted before that failure became known.
Repeated failure therefore ages the last target and still triggers HOLD.
GP and buffers retain their previous valid state as before. No concurrency,
worker process or middleware is added.

**Replacement geometry cache.** `MultiFidelityGaussianProcess` keeps at most
one retained-data/grid geometry: projected query covariance, influence vectors,
weighted norms, precision diagonal and $J(D)$. It reuses these only for an
identical fitted factor/kernel signature, exact query coordinates and normalized
weights. Successful fitting invalidates the cache. Candidate-dependent solves
and all swap/verification equations remain unchanged. The cache is bounded by
$O(N|G|)$ storage and never stores an explicit covariance inverse. Tests compare
cached results, changed weights and refitting with fresh calculations.

**Failed-health snapshot.** `health_failure_snapshot` in
`docker/timed_mission.py` copies the runtime health reasons and timestamp plus
target/central/pose/plan/command ages. `ros_timed_mission.execute` saves it to
`mission.health_failure` and a `mission_health_failure` event before HOLD.
`ReadinessNode.report` adds last observed command receipt time to its statistics;
this does not alter its 0.25 s rejection threshold. This snapshot preserves the
trigger even if the final post-HOLD report becomes ready again.

**Validation clock and metric.** `docker/deployment_timing_validation.py`
uses the actual central runtime, planners and command gate with a controlled
clock, fixed measured poses, fresh leases and 1.45 s injected compute durations
for 240 s. It checks commands at 20 Hz for three vehicles, including both end
points: $3(240\cdot20+1)=14403$ checks. Rejections count gate calls returning
no command; no motion integration, tracking or live mission is simulated.
The comparison completion-only publisher is given ideal fresh completion
stamps, so it isolates missing pre-update publication rather than penalizing
old start stamps. Its maximum target age is 2.45 s, versus 1.45 s after the fix,
with 2,583 versus zero rejected command checks. These are controlled timing
results, not a completed moving SITL experiment.

## Implemented SITL planar circular-obstacle CBF

The optional ground-role command filter treats map-plane velocity as the input:
$\dot p=v$. It is separate from the unicycle simulation prototype and does not
change the GP or planner objective. For circular center $c_j$, physical radius
$r_j$ and configured combined clearance $m$, define

$$
h_j(p)=\|p-c_j\|^2-(r_j+m)^2.
$$

The continuous ideal constraint is
$2(p-c_j)^T v+\alpha h_j(p)\geq0$. The exact command implementation solves

$$
v^*=\arg\min_v \|v-v_{nom}\|^2,\qquad
2(p-c_j)^Tv\geq-\alpha h_j(p),\quad \|v\|\leq v_{max},
\quad (l_k-p_k)/T\leq v_k\leq(u_k-p_k)/T.
$$

Here $[l_k,u_k]$ is the existing geofence after its margin, and $T$ is the
configured stopping horizon. The 2D solver enumerates interior/radial projection,
line projections, pairwise line intersections and line/speed-circle intersections,
then selects the feasible candidate of minimum squared error. It uses linear
solves, not matrix inversion. It runs at command rate using current validated
pose, rather than triggering GP updates. Missing configuration disables it;
aerial-role commands bypass it. An interior/invalid/infeasible filter result
produces zero planar velocity, an explicit status and throttled warning, subject
to the remaining command gates. Holding inside an inflated disk does not restore
safety and requires operator recovery.

For exact held velocity with step $\Delta t$, the implemented model satisfies

$$
h_j(p+\tau v)=h_j(p)+2\tau(p-c_j)^Tv+\tau^2\|v\|^2
\geq(1-\alpha\tau)h_j(p),\quad 0\leq\tau\leq\Delta t.
$$

Thus an initially safe disk constraint remains safe for ideal tracking if
$\alpha\Delta t\leq1$. The deterministic rollout uses $\Delta t=0.05$ s
and $\alpha=1$ per second. Physical tracking, telemetry latency, acceleration
and stopping dynamics are not captured by this argument. The filter ensures no
global convergence: obstacle-induced stalls remain possible.

Equation-to-code map: `src/core/planar_cbf.py::filter_velocity` implements the
projection; `docker/deployment_obstacle_filter.py::ObstacleFilter` inflates
manifest circles and reports filter state; `docker/deployment_command_gate.py`
applies it within existing acceptance gates; `docker/ros_agent.py::_command`
invokes it per command tick. `examples/plot_sitl_obstacle_cbf_milestone.py` uses
real Lloyd proposals with fixed truth-weighted centroids for ideal-tracking
comparison, not a recorded flight or an estimator benchmark.
